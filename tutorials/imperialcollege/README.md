# Imperial College Case

## Overview

The Imperial College engine case is a simplified reciprocating engine benchmark for studying in-cylinder flow, mesh motion, and turbulence. This guide walks you through the setup, highlighting both the general workflow and the mesh configuration details from `constant/engineDict`.

## 1. Dependencies

- OpenFOAM environment (commonly OpenFOAM-dev)
- ParaView or another Linux visualization tool
- Python 3 for optional plotting/post-processing utilities
- Optional Python packages: numpy, matplotlib, scipy

## 2. Case Structure and Key Files

- **Allclean**: Removes generated run-time and mesh artifacts
- **Allmesh**: Generates remesh schedule and creates mesh sequence
- **Allrun**: Initializes and runs the simulation
- **remeshInstants.py**: Helper to inspect/plot remeshing schedule
- **system/**: Solver, decomposition, and sampling dictionaries
- **constant/**: Geometry, dynamic mesh, and mesh-time related data
  - **engineDict**: Central to mesh setup—defines moving parts, remeshing schedule, and mesh controls
    - **Purpose**: Brings together the information needed to generate the engine mesh consistently across time:
      - the remeshing time range and step size
      - global mesh sizing and region refinement
      - patch-specific motion definitions
      - patch-specific mesh controls and layer settings
    - **Main Sections**:
      - **`times`**: Mesh times loaded from `constant/meshTimes` using `#includeIfPresent "${FOAM_CASE}/constant/meshTimes";`. This allows remeshing instants to be managed separately and regenerated by scripts.
      - **`remeshControl`**: Sets the remeshing window and frequency:
        - `startInstant`: first remesh instant
        - `endInstant`: last remesh instant
        - `stepSize`: time increment for remeshing
        - `forcedRemeshInstants`: explicitly forced remesh times
      - **`meshControl`**: Base mesh resolution and region-based refinement:
        - `cellSize`: base cell size
        - `insidePoints`: region-defining points
        - `patchInfo`: default patch grouping
        - `surfaceRefinement`: refinement near surfaces
        - `regionRefinement`: geometric refinement zones
        - `layerControl`: boundary-layer settings
      - **`patches`**: Defines moving and fixed engine patches:
        - `piston`: translation motion (crank-connecting-rod model)
        - `valve`: moving valve surfaces
        - `liner`: scaling motion coupled to piston
        - `outlet`: fixed outlet patch
        - Each patch can override global mesh controls with its own `meshControl`.
    - **Notes**:
      - `engineDict` is designed to work with the tutorial scripts, especially `Allmesh` and `Allrun`.
      - Changes to motion or refinement parameters can affect remeshing and mesh compatibility—validate with case tools.
      - The dictionary uses OpenFOAM syntax and includes nested dictionaries and file references; keep formatting consistent.
- **0.orig/**: Initial conditions template

## 3. Running the Case

From the `tutorials/imperialcollege` directory:

```bash
./Allclean
./Allmesh
./Allrun
```

Recommended pre-check:

```bash
compareMeshes -referenceMesh 0
```

Optional: plot remesh instants with:

```bash
python3 remeshInstants.py
```

## 4. Practical and Modeling Notes

- Source your OpenFOAM environment before running scripts.
- The case can be computationally expensive depending on decomposition and mesh count.
- GNU Parallel can be used for concurrent meshing.
- Adjust `generateMesh` and decomposition settings for your hardware.
- Utility logs help debug mesh and motion issues.
- The case is axisymmetric and uses mesh motion for piston movement.
- Review boundary/turbulence setup in `0.orig` and `system/` for your solver/version.
- Intended as a benchmark, not a production engine model.
